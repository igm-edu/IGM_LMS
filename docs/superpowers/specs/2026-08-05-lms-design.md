# 사내 e러닝 LMS 설계 문서

작성일: 2026-08-05
기반 문서: `LMS_기능명세서_v0.3.docx`
저장소: `igm-edu/IGM_LMS`

이 문서는 기능명세서 v0.3을 구현 가능한 수준으로 구체화한 설계안이다. 명세서와 어긋나는 부분은 각 절에 이유를 함께 적었다.

---

## 1. 목표와 범위

IGM 공개과정 수강생을 대상으로 e러닝 수강, 시청시간 기반 출결 판정, 수료 퀴즈, 수료증 발급을 하나의 흐름으로 처리하는 내부용 LMS를 만든다. 서버 운영 비용 없이 GitHub Pages와 Google 계정 자산만으로 구성한다.

명세서 9장의 확장 항목(알림 발송, 복수 강사, 결제 연동, 모바일 최적화)은 이번 범위에 포함하지 않는다.

## 2. 확정된 제약

브레인스토밍 과정에서 확정된 사항이다.

- 영상은 이미 보유한 외부 서버의 mp4 직링크로 제공한다. 해당 URL은 HTTPS여야 하며 Range 요청을 지원해야 한다. 두 조건은 실제 URL을 받는 시점에 검증한다.
- 특정 오픈 마감이 없다. 단계를 쪼개 급히 내보내기보다 명세서 범위를 순차적으로 제대로 구현한다.
- Sheets와 Apps Script를 소유하는 계정은 **개인 Gmail**이다. 따라서 Apps Script 하루 총 실행시간 90분, 메일 발송 100통이라는 무료 계정 할당량이 설계 상수로 작용한다.
- 개인정보는 명세서대로 전부 수집한다(이름, 이메일, 연락처, 소속, 직급, 생년월일). 대신 수집·이용 동의 절차와 보관 기간을 함께 둔다.
- 아키텍처는 B안을 채택한다. Apps Script + Sheets 구조를 유지하되 시청 로그 전송을 이벤트 기반으로 줄이고, 출결·수료 집계는 시간 트리거로 분리한다.

### 2.1 개인 Gmail 계정에 따른 운영 위험

회사 교육 데이터와 외부 기업 임직원의 개인정보가 담당자 개인 계정에 보관된다. 담당자 변경이나 감사 상황에서 문제가 될 수 있으므로, 운영 계정을 회사 Workspace로 옮길 수 있게 되면 이전하는 것을 권한다. 설계상 계정 이전은 스프레드시트와 Apps Script 프로젝트의 소유권 이전만으로 가능하도록 외부 종속성을 두지 않는다.

## 3. 아키텍처

브라우저가 GitHub Pages에서 정적 파일을 받아 실행하고, 데이터가 필요할 때 Apps Script 웹앱 한 곳으로 요청을 보낸다. 웹앱은 요청의 `action` 값으로 분기해 Google Sheets를 읽고 쓴다.

| 구성 요소 | 역할 |
|---|---|
| GitHub Pages | 정적 프론트엔드 호스팅, 화면 렌더링과 사용자 인터랙션 |
| Apps Script 웹앱 | 인증, 데이터 읽기·쓰기, 퀴즈 채점, 출결·수료 판정 API |
| Apps Script 시간 트리거 | 출결·수료 재집계, 수료증 발급 |
| Google Sheets | 데이터 저장소 |
| Google Drive | 발급된 수료증 PDF 보관 |
| 외부 영상 서버 | mp4 직링크 제공 |

### 3.1 CORS 제약

Apps Script 웹앱은 브라우저의 CORS 사전 요청(preflight)에 응답하지 못한다. 따라서 모든 요청은 사전 요청이 발생하지 않는 단순 요청 조건을 지켜야 한다.

- 본문은 JSON 문자열로 만들되 `Content-Type`은 `text/plain;charset=utf-8`로 보낸다.
- 사용자 정의 헤더를 쓰지 않는다. 세션 토큰은 헤더가 아니라 본문에 담는다.
- 서버는 `e.postData.contents`를 문자열로 받아 직접 파싱한다.

이 제약을 모르면 개발 초반에 원인을 찾기 어려운 CORS 오류가 발생한다.

### 3.2 백엔드 코드 관리

Apps Script 코드는 웹 편집기에 두지 않고 `clasp`로 저장소 안에서 관리한다. 프론트엔드와 백엔드 변경을 한 커밋으로 묶고 변경 이력을 남기기 위해서다. 배포는 `clasp push` 후 웹앱 버전을 갱신한다.

## 5. 데이터 모델

하나의 스프레드시트 안에 13개 시트를 둔다. 명세서 본문은 "11개 탭"이라고 적었으나 실제 열거된 시트는 12개이며, 여기에 ErrorLog를 더해 13개가 된다.

행 1행은 헤더이고 2행부터 레코드다. A열은 각 시트의 기본키다.

### 5.1 명세서 대비 변경점

**결합키 도입.** Sheets에는 인덱스가 없어 두 개 이상의 열로 행을 찾으려면 전체를 훑어야 한다. 회원×차시나 회원×클래스처럼 조합마다 정확히 한 행만 존재하는 시트는 두 ID를 결합한 값을 기본키로 삼는다. A열만 읽어 위치를 찾을 수 있고, 같은 조합이 중복 생성되는 사고도 구조적으로 막힌다.

- `WatchLogs.watch_log_id` = `{user_id}_{lesson_id}`
- `Attendance.attendance_id` = `{user_id}_{class_id}`
- `Enrollments.enrollment_id` = `{user_id}_{class_id}`

**행 인덱스 캐시.** 시트별로 기본키에서 행 번호를 찾는 맵을 `CacheService`에 5분간 보관한다. 관리자가 시트를 직접 편집해 행이 밀릴 수 있으므로, 값을 쓰기 전에 해당 행의 A열이 기대한 기본키와 일치하는지 확인한다. 어긋나면 캐시를 버리고 다시 만든 뒤 진행한다.

**세션 토큰 해시 저장.** Sessions 시트에는 토큰 원문 대신 해시를 저장한다. 스프레드시트가 유출되어도 그 값으로 바로 로그인할 수 없게 하기 위해서다.

**개인정보 동의 기록.** Users에 `consent_at`과 `retention_until`을 추가한다. 회원가입 화면에 수집·이용 동의 항목을 두고, 동의하지 않으면 가입이 진행되지 않는다. `retention_until`의 기본값은 가입일로부터 3년으로 하고, 수료가 확정되면 수료일 기준 3년으로 갱신한다. 만료된 계정을 자동으로 지우지는 않고 관리자 화면에 목록으로 표시해 사람이 판단하게 한다.

**추가 전용 시트.** QuizAttempts와 QuizAnswers는 기록을 남기기만 하고 수정하지 않는다. 채점 결과를 사후에 바꾸지 않기 위해서다.

### 5.3 초기 구성 함수

`schema.js`가 13개 시트의 이름과 헤더를 정의하는 단일 출처가 되고, `sheet.js`와 `setup.js`가 모두 이 정의를 참조한다.

- `setupSheets()` — 없는 시트를 만들고 헤더를 쓴다. 이미 있는 시트는 헤더만 대조해 빠진 열을 뒤에 추가한다. **기존 시트를 지우거나 비우지 않는다.**
- `seedAdmin(email, password)` — 최초 관리자 계정 1건을 만든다. 이미 admin이 있으면 아무것도 하지 않는다.
- `resetAllSheets(confirm)` — 전체 초기화. `confirm`이 정해진 문자열과 일치할 때만 동작한다. 실수로 수강 이력이 지워지는 것을 막기 위해 별도 함수로 분리했다.

## 6. API 규약

단일 엔드포인트에 POST하고 본문의 `action`으로 분기한다.

요청: `{ "action": "...", "token": "...", "payload": { ... } }`
응답: `{ "ok": true, "data": ... }` 또는 `{ "ok": false, "error": { "code": "...", "message": "..." } }`

Apps Script 웹앱은 항상 HTTP 200을 반환하므로 성공 여부는 본문의 `ok`로만 판단한다.

| action | 권한 | 설명 |
|---|---|---|
| `auth.signup` | 공개 | 회원가입 (동의 필수) |
| `auth.login` | 공개 | 로그인, 토큰 발급 |
| `auth.logout` | 회원 | 세션 폐기 |
| `auth.me` | 회원 | 본인 정보 조회 |
| `auth.updateProfile` | 회원 | 본인 정보 수정 |
| `class.list` | 회원 | 클래스 목록 |
| `class.get` | 회원 | 클래스 상세와 차시 목록 |
| `class.enroll` | 수강생 | 수강 신청 |
| `class.upsert` | 관리자 | 클래스 개설·수정 |
| `lesson.upsert` | 관리자 | 차시 등록·수정 |
| `lesson.delete` | 관리자 | 차시 삭제 |
| `watch.get` | 수강생 | 본인 시청 기록 조회 (이어보기) |
| `watch.update` | 수강생 | 시청 위치 갱신 |
| `quiz.get` | 수강생 | 퀴즈와 문항 조회 (정답 제외) |
| `quiz.submit` | 수강생 | 응시 제출과 자동 채점. 재응시 불허 클래스에서 이미 응시 기록이 있으면 거부한다 |
| `quiz.upsert` | 관리자 | 퀴즈·문항 등록·수정 |
| `report.myStatus` | 수강생 | 본인 출결·수료 현황 |
| `report.classSummary` | 강사·관리자 | 클래스별 수강생 현황 |
| `report.overview` | 관리자 | 전체 통계 |
| `user.list` | 관리자 | 회원 검색 |
| `user.update` | 관리자 | 회원 상태·역할 변경 |
| `user.resetPassword` | 관리자 | 임시 비밀번호 발급 |
| `cert.myList` | 수강생 | 본인 수료증 목록 |
| `cert.download` | 수강생 | 본인 수료증 다운로드 링크 발급 |

권한 검사는 각 처리 함수에 흩어 두지 않고, 라우팅 표에 action별 요구 역할을 선언해 진입 지점에서 한 번에 확인한다. 강사는 `instructor_id`가 본인인 클래스만 조회할 수 있으며, 이 범위 검사는 `report.classSummary` 처리부에서 추가로 수행한다.

`quiz.get`은 정답 번호를 응답에 포함하지 않는다. 채점은 전적으로 서버에서 한다.

## 7. 인증과 보안

**비밀번호.** 계정마다 16바이트 무작위 소금값을 만들고 PBKDF2 방식으로 반복 해싱한다. Apps Script에는 bcrypt류 표준 라이브러리가 없어 `Utilities.computeHmacSha256Signature`를 반복 호출해 직접 구현한다. 반복 횟수는 **10,000회로 구현하되**, 실제 환경에서 로그인 응답 시간을 측정해 1초를 넘으면 넘지 않는 선까지 낮추고 여유가 있으면 올린다. 저장 형식에 반복 횟수를 포함시키므로 나중에 값을 바꿔도 기존 계정은 그대로 로그인된다.

**세션 토큰.** `Utilities.getUuid()`를 두 번 이어 붙여 만든다. 이 함수는 Java의 보안 난수를 사용하므로 `Math.random()`과 달리 예측하기 어렵다. 원본은 브라우저에만 전달하고 시트에는 SHA-256 해시만 저장한다. 유효기간은 24시간이며, 요청 시점에 만료가 6시간 이내로 남았으면 자동 연장한다. 긴 영상을 시청하는 도중 로그아웃되는 상황을 막기 위해서다.

**로그인 시도 제한.** Apps Script는 접속자 IP를 알 수 없어 이메일 기준으로만 센다. 같은 계정에 5회 연속 실패하면 10분간 잠근다. 카운터는 `CacheService`에 둔다.

**비밀번호 재설정.** 1차 버전은 관리자가 임시 비밀번호를 발급하는 방식으로 한다. 메일 자동 발송은 개인 Gmail의 하루 100통 한도를 다른 용도와 다투게 되므로, 필요한 용도를 확정한 뒤에 붙인다.

**웹앱 배포 설정.** "나로 실행 / 모든 사용자 액세스 가능"으로 배포한다. 엔드포인트 URL이 공개되어도 유효한 토큰 없이는 어떤 데이터도 반환하지 않는다.

**XSS 대응.** 토큰을 `localStorage`에 보관하므로 스크립트 주입 취약점이 생기면 탈취될 수 있다. 외부 스크립트를 페이지에 넣지 않고, 회원 이름·클래스명처럼 사람이 입력한 값은 HTML로 조립하지 않고 `textContent`로만 넣는 규칙을 코드 전반에 적용한다.

**시트 접근 권한.** 스프레드시트와 Drive의 수료증 폴더는 소유 계정만 접근할 수 있게 두고, 외부에는 Apps Script API를 통해서만 간접 노출한다.

## 8. 시청 측정

### 8.1 브라우저 측

`timeupdate` 이벤트마다 로컬에서만 최대 도달 지점을 갱신한다. 재생 위치가 직전 값보다 **1.5초 이내로 증가한 경우에만** 실제 재생으로 인정한다. 그보다 크게 뛰면 구간 이동으로 보고 누적하지 않는다.

배속은 `ratechange`를 감시해 1이 아니면 즉시 1로 되돌리고, 플레이어 컨트롤에서도 배속 항목을 숨긴다.

서버 전송은 다음 네 시점에만 일어난다.

- 시청률이 직전 전송 시점보다 5% 이상 갱신되었을 때
- 일시정지했을 때
- 탭이 백그라운드로 전환되었을 때 (`visibilitychange`)
- 영상이 끝났을 때

페이지를 닫는 순간에는 일반 요청이 중간에 끊기므로 `navigator.sendBeacon`으로 마지막 값을 보낸다. 본문 형식은 앞서 정한 CORS 조건과 동일하게 `text/plain` Blob으로 만든다.

1시간짜리 영상 하나를 처음부터 끝까지 볼 때 요청은 20여 회에 그친다. 명세서의 10~15초 주기 방식이었다면 240회였다.

### 8.2 서버 측 검증

**시청 시간을 재는 코드가 브라우저에 있는 이상 값은 조작될 수 있다. 실질적인 방어선은 서버다.** `watch.update`는 세 가지를 검사하고, 하나라도 걸리면 저장하지 않는다.

1. 기존 `max_watched_sec`보다 작은 값이면 무시한다. 값은 단조 증가만 한다.
2. `video_duration_sec`을 넘는 값은 거부한다.
3. `last_updated_at` 이후 실제로 흐른 시간보다 시청 시간이 더 많이 늘어난 요청은 거부한다.

세 번째가 핵심이다. 30초 전에 기록을 보낸 계정이 곧바로 10분치가 늘었다고 주장하면 물리적으로 불가능하므로 받아들이지 않는다. 시계 오차와 네트워크 지연을 감안해 실제 경과 시간에 10초의 여유를 더한 값까지 허용한다.

저장에 성공하면 해당 차시가 속한 클래스를 재집계 대상으로 표시한다.

## 9. 출결·수료·수료증

### 9.1 재집계 트리거

15분 간격 시간 트리거가 동작한다. 트리거는 스크립트 속성에 저장된 재집계 대상 클래스 목록을 읽고, 비어 있으면 즉시 종료한다. 목록에 값이 있을 때만 실제 계산을 수행하므로 평소 실행시간 소비가 거의 없다.

이 방식이 필요한 이유는 개인 Gmail의 하루 90분 실행시간을 트리거와 사용자 요청이 나눠 쓰기 때문이다. 매 실행마다 전체를 집계하면 트리거만으로 한도의 절반을 소모한다.

목록 갱신은 `LockService`로 보호한다. 표시가 누락되거나 관리자가 시트를 직접 수정해 어긋나는 경우에 대비해, 하루 한 번은 목록과 무관하게 전체를 재집계한다.

이 하루 한 번 실행에서 정리 작업도 함께 처리한다. 만료된 Sessions 행과 90일이 지난 ErrorLog 행을 삭제한다. 두 시트는 그냥 두면 계속 늘어나기만 해서 시간이 지날수록 조회가 느려진다.

### 9.2 판정 규칙

클래스에 속한 모든 차시의 시청률을 평균해 `watch_rate_threshold`와 비교한다. **분모는 클래스의 전체 차시 수이며, 시청 기록이 없는 차시는 0%로 계산한다.** 차시를 아예 열어보지 않은 것과 절반만 본 것이 같은 취급을 받지 않게 하기 위해서다.

퀴즈는 차시별 최고점을 구해 평균하고 `quiz_pass_score`와 비교한다. 여기서도 응시하지 않은 차시는 0점으로 본다. 재응시가 허용되지 않은 클래스에서는 `quiz.submit`이 두 번째 제출을 애초에 거부하므로 기록이 하나뿐이다.

두 기준을 모두 충족하면 `is_completed`를 참으로 바꾸고 `completed_at`을 기록한 뒤, Enrollments의 상태를 "수료"로, Users의 `retention_until`을 수료일 기준 3년으로 갱신한다. 이미 수료 처리된 레코드는 다시 판정하지 않는다.

### 9.3 수료증 발급

수료가 확정되면 Google Slides 템플릿을 복사해 이름·소속·과정명·수료일·발급번호를 채우고 PDF로 내보내 Drive 폴더에 저장한다. 업무 폴더의 `수료증 템플릿.png`를 배경으로 사용한다.

발급번호는 `IGM-{연도}-{클래스ID}-{일련번호}` 형식으로 만든다.

PDF에는 이름과 소속이 담기므로 파일은 공개하지 않는다. Certificates 시트에는 링크가 아닌 Drive 파일 ID를 저장하고, `cert.download`가 요청자가 본인임을 확인한 뒤에만 접근 가능한 링크를 만들어 응답한다.

## 10. 에러 처리

프론트엔드의 `api.js`가 모든 통신을 담당한다. 네트워크 오류는 간격을 늘려가며 두 번까지 자동 재시도하고, 응답의 오류 코드가 토큰 만료를 가리키면 저장된 토큰을 지우고 로그인 화면으로 보낸다. 그 외 오류는 화면에 사람이 읽을 수 있는 문구로 표시한다.

서버는 라우팅 진입 지점에서 모든 예외를 잡아 ErrorLog 시트에 요청 종류·회원·시각·메시지·스택을 남긴다. 사용자에게는 내부 오류 내용을 그대로 노출하지 않고 코드와 일반 문구만 반환한다.

같은 행을 동시에 고치는 상황은 `LockService`로 직렬화한다. 잠금 대기가 10초를 넘으면 예외를 삼키지 않고 "잠시 후 다시 시도" 응답을 돌려준다.

Apps Script 할당량을 초과하면 웹앱 자체가 응답하지 않으므로, 프론트는 재시도가 모두 실패한 경우 일시적인 서비스 장애임을 안내한다.

## 11. 테스트 전략

**Sheets에 의존하지 않는 순수 계산 로직을 `lib/calc.js`와 `lib/hash.js`로 분리하는 것이 이 전략의 전제다.** 다음 함수들이 여기에 속하며 Node에서 단위 테스트한다.

- 비밀번호 해시 생성과 검증
- 시청률 계산
- 시청 시간 갱신 허용 여부 판정 — 조작을 막는 핵심 로직이므로 경계값을 집중적으로 검증한다. 값이 감소하는 경우, 영상 길이를 넘는 경우, 경과 시간보다 많이 증가한 경우, 허용 여유의 경계에 걸치는 경우를 모두 다룬다.
- 퀴즈 채점과 합격 판정
- 클래스 수료 판정 (재응시 허용 여부에 따른 점수 선택 포함)
- 발급번호 생성

Sheets를 실제로 읽고 쓰는 부분은 별도의 테스트용 스프레드시트를 두고 Apps Script 편집기에서 통합 테스트 함수를 실행해 확인한다. `setupSheets()`가 기존 데이터를 보존하는지, 행 인덱스 캐시가 어긋났을 때 복구되는지가 주요 검증 대상이다.

프론트엔드는 시청 시간 누적 판정을 순수 함수로 떼어내 테스트하고, 화면 동작은 브라우저에서 확인한다.

## 12. 이후 확정할 사항

아래는 구현을 막지는 않으나 진행 중 확인이 필요한 항목이다. 각 항목에 현재 적용할 값을 함께 적었다.

- 영상 서버 URL의 HTTPS 지원과 Range 요청 지원 여부 — URL을 받는 즉시 검증한다. 미지원이면 8장의 측정 설계를 재검토해야 한다.
- PBKDF2 반복 횟수 — 10,000회로 구현하고 실측 후 조정
- 수료증 서식 — 1차는 `수료증 템플릿.png`를 배경으로 한 기본 텍스트 서식
- 개인정보 보관 기간 — 가입일 또는 수료일 기준 3년
- 운영 계정의 회사 Workspace 이전 시점 — 미정
